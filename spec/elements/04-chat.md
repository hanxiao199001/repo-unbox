# 组件群聊 `kc-chat`

## 它是什么

把代码里各个部分之间的协作，演成一段微信群聊。**全课至少出现一次。**

## 学员看到什么

一个聊天窗口。初始是空的（或只有第一条）。每条消息左边一个圆形头像（一个字或一个表情），
右边一个气泡，气泡顶上是发言者名字，下面是内容。不同角色用不同颜色，全课保持一致。

窗口下方三个按钮："下一条"、"全部播放"、"重放"，以及一个进度提示"3 / 7 条"。

## 学员能做什么

| 动作 | 结果 |
|---|---|
| 点"下一条" | 先出现打字指示（三个跳动的点，头像是**即将发言那个角色**的），停顿约 0.8 秒，然后消息出现 |
| 点"全部播放" | 按固定间隔自动逐条播放，直到播完 |
| 点"重放" | 全部消息收回，回到初始，进度归零 |

**打字指示的头像必须是下一个发言者**，而不是通用的问号——这是让"谁在说话"这件事被看见的关键。

## 状态怎么变

一个游标：已显示到第几条。

- "下一条"：游标 +1。已到末尾时无效果，不报错。
- "全部播放"：反复推进游标直到末尾。播放期间再点"下一条"不应造成重复或跳条。
- "重放"：游标归零，全部消息隐藏。

消息出现时有一次淡入上移，不循环。

## 数据契约

| 名字 | 用在哪 | 必填 |
|---|---|---|
| `kc-chat` | 根节点 | 是 |
| 标识符 | 根节点 | 是 |
| `kc-chat__stream` | 消息列表 | 是 |
| `kc-chat__message` | 每条消息 | 是 |
| `data-kc-speaker` | 每条消息 | 是 |
| `kc-chat__avatar` | 头像 | 是 |
| `kc-chat__bubble` | 气泡 | 是 |
| `kc-chat__speaker` | 气泡里的发言者名 | 是 |
| `kc-chat__typing` | 打字指示 | 是 |
| `kc-chat__next` / `kc-chat__all` / `kc-chat__replay` | 三个按钮 | 是 |
| `kc-chat__progress` | 进度提示 | 是 |

同一个 `data-kc-speaker` 的所有消息，头像和颜色必须一致。
实现应当从消息里推断每个角色的头像，而不要求内容作者在打字指示里重复写一遍。

## 内容规则

- **5–8 条**。少于 5 条撑不起，多于 8 条学员会失去耐心。
- 每条一到两句，**用角色的口吻说话**，不要写成旁白。
- 角色名用代码里的真实名字（文件名、函数名），英文原样，不翻译。
- 消息内容是中文，但里面提到的标识符、状态码、报错保持英文。
- 全课的角色配色一致：同一个文件在任何模块里都是同一个颜色。

## 失败与边界

- 缺标识符 → 构建失败（页面上多个聊天窗会互相干扰）。
- 缺"下一条"或"重放"按钮 → 构建失败。
- 消息没有声明发言者 → 打字指示无法确定头像，构建失败。
- 脚本未运行 → **所有消息应当直接全部可见**，按钮无效但不消失。

## 验收标准

- [ ] 打字指示的头像是下一个发言者
- [ ] "全部播放"过程中重复点击不会跳条或重复
- [ ] "重放"后可以完整再走一遍
- [ ] 进度提示与实际显示条数一致
- [ ] 同一角色在全课颜色一致
- [ ] 键盘可以触发三个按钮
