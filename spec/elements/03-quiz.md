# 选择题 `kc-quiz`

## 它是什么

一组单选题，答完一起对答案，每题给解释。放在模块内容之后、输出题之前，当热身。

## 学员看到什么

一个方框，里面是若干道题。每道题：题干一行，下面是 2–4 个选项，每个选项左边一个空心圆点。
最下面两个按钮："看看答案"和"再来一次"。对完答案后，每道题下方展开一段解释文字。

## 学员能做什么

| 动作 | 结果 |
|---|---|
| 点一个选项 | 该题内其他选项取消选中，这个被选中 |
| 点"看看答案" | 全部题目同时判定；对错以颜色和圆点样式区分；每题展开解释；所有选项变为不可点 |
| 点"再来一次" | 清空全部选择、收起全部解释、恢复可点 |

**一题只能选一个。** 未作答的题在对答案时不算错，只是没有结果——不要惩罚跳过。

## 状态怎么变

每道题三个状态：

| 状态 | 界面 |
|---|---|
| 未答 | 全部选项中性；无解释 |
| 已选未判 | 被选项高亮；无解释 |
| 已判 | 选对：该项标为正确；选错：该项标为错误，**同时把正确项也标出来**；展开解释 |

"看看答案"把所有"已选未判"推进到"已判"；"再来一次"把所有题拉回"未答"。

## 解释文字

每题两段，二选一显示：

- **答对时**：简短肯定，并点出背后的原理——"对。因为 X 在这个架构里负责 Y。"
- **答错时**：**不许只说"错了，答案是 B"**。要说明该往哪儿想，而且要教到新东西——
  "再看一眼提交函数的最后一行——页面不是自己把新待办画上去的，它是重新问了一遍。"

语气不带评判。**页面上不许出现"你答对了 3/5"这类计分。**

## 数据契约

| 名字 | 用在哪 | 必填 |
|---|---|---|
| `kc-quiz` | 根节点 | 是 |
| 标识符 | 根节点 | 是 |
| `kc-quiz__question` | 每道题 | 是 |
| `data-kc-answer` | 每道题 | 是 |
| `data-kc-right` | 每道题（答对时的解释） | 是 |
| `data-kc-wrong` | 每道题（答错时的解释） | 是 |
| `kc-quiz__prompt` | 题干 | 是 |
| `kc-quiz__option` | 每个选项 | 是 |
| `data-kc-value` | 每个选项 | 是 |
| `kc-quiz__marker` | 选项左边的圆点 | 是 |
| `kc-quiz__feedback` | 解释区 | 是 |
| `kc-quiz__check` / `kc-quiz__reset` | 两个按钮 | 是 |
| `kc-is-selected` / `kc-is-right` / `kc-is-wrong` | 选项状态 | — |

`data-kc-answer` 的值必须等于本题某个选项的 `data-kc-value`。

## 内容规则

- 一个模块一组，**3–5 道**。
- **考应用，不考记忆。** 按价值从高到低：给一个没见过的新情况让他解决；调试场景
  "用户说 X 坏了，你先去哪儿找"；架构决策"这段逻辑放前端还是后端"；追踪"数据走了哪条路"。
- **不许考**：术语定义（那是术语气泡的活）、文件名背诵、语法细节、
  任何往上翻一屏就能抄到答案的东西。
- 选项 2–4 个，长度相近，不许出现明显凑数的荒唐选项。

## 失败与边界

- 某题没有标注正确答案 → 构建失败。
- 正确答案对不上任何选项 → 构建失败。
- 缺解释文字 → 构建失败。
- 脚本未运行 → 题目和选项照常可读，**解释应当直接可见**（宁可剧透，也不要变成死页面）。

## 验收标准

- [ ] 一题只能选一个
- [ ] 对答案后选错的题同时标出正确项
- [ ] 未作答的题不产生任何负面反馈
- [ ] "再来一次"完全复原
- [ ] 页面上找不到任何分数
- [ ] 键盘能选中选项并触发两个按钮
