# 架构图 `kc-map`

## 它是什么

把系统里的角色画成分区的方块图，点一个方块看它负责什么。

## 学员看到什么

若干个分区（例如"浏览器"、"服务器"、"外部服务"），每个分区里若干个方块，
方块上是图标加名字。图下方有一块说明区，初始写着"点任意一个方块，看它负责什么"。

## 学员能做什么

| 动作 | 结果 |
|---|---|
| 点一个方块 | 该方块高亮；其余方块取消高亮；说明区换成这个方块的说明 |
| 键盘聚焦后回车 | 同上 |

再点同一个方块，保持选中，不切换回默认文字。

## 状态怎么变

一个当前选中项，可以为空（初始）。高亮是排他的。

## 数据契约

| 名字 | 用在哪 | 必填 |
|---|---|---|
| `kc-map` | 根节点 | 是 |
| `kc-map__zone` | 每个分区 | 是 |
| `kc-map__zone-name` | 分区名 | 是 |
| `kc-map__node` | 每个方块 | 是 |
| `data-kc-about` | 每个方块 | 是 | 点击后显示的说明 |
| `kc-map__icon` / `kc-map__name` | 方块的图标与名字 | 是 |
| `kc-map__about` | 说明区 | 是 |
| `kc-is-current` | 选中的方块 | — |

说明区**靠所属图定位，不带标识符**，一页放两张图也不会互相干扰。

## 内容规则

- 分区 2–4 个，方块总数 4–8 个。
- 方块名用**真实文件名**，英文原样。
- 说明 1–3 句，讲"它负责什么、不负责什么"。
  "只有它碰硬盘，所以数据不对的时候先来这里找"比"数据访问层"有用得多。
- 分区名用中文。

## 失败与边界

- 某方块没有说明 → 构建失败。
- 说明区带标识符 → 构建失败。
- 脚本未运行 → 图照常可见，说明区停在默认文字。

## 验收标准

- [ ] 任意时刻最多一个方块高亮
- [ ] 同一页面两张图互不干扰
- [ ] 键盘能聚焦并选中每个方块
- [ ] 窄屏下分区改为纵向排列，不溢出
