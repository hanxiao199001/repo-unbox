# 提示框 `kc-note`

## 它是什么

从正文里跳出来的一个方块，放一条通用原理或一句警告。用来标记"原来如此"的时刻。

## 学员看到什么

一个带左侧粗边和图标的方块，里面一个小标题加一两句话。三种语气，靠左边框颜色和图标区分：

| 语气 | 用在什么时候 |
|---|---|
| 洞察 | 通用的计算机原理，值得记住的那种 |
| 提示 | 知道了更好、不知道也不影响的补充 |
| 警告 | 常见错误、容易踩的坑 |

## 学员能做什么

无交互。里面的术语照常有气泡。

## 状态怎么变

无状态。

## 数据契约

| 名字 | 用在哪 | 必填 |
|---|---|---|
| `kc-note` | 根节点 | 是 |
| `data-kc-tone` | 根节点 | 是 | `insight` / `info` / `warning` |
| `kc-note__icon` | 图标 | 是 |
| `kc-note__title` | 小标题 | 是 |
| `kc-note__body` | 正文 | 是 |

## 内容规则

- **一个模块最多 2 个**。满屏提示框等于没有提示框。
- 内容必须是**跳出这个项目也成立的通用原理**，例如"关注点分离"、"单一出口"。
  只在本项目成立的细节写正文里，不要放提示框。
- 正文 1–3 句。
- 如果这条原理有工程界的通用名字，**把名字写出来**——学员将来要用这个词去问 AI。

## 失败与边界

- 语气不在三个值里 → 构建失败。
- 一个模块超过 2 个 → 构建时提示（不失败）。

## 验收标准

- [ ] 三种语气在灰度截图里仍可区分（靠图标，不只靠颜色）
- [ ] 一个模块不超过 2 个
