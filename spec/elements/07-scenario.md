# 场景题 `kc-scenario`

## 它是什么

一段情境铺垫，加一道选择题。用在"光看题干说不清楚"的时候。它是选择题的外壳，不是独立元素。

## 学员看到什么

一个带左侧强调边的方块，顶上一个小标签"场景"，下面两三句话把情境讲清楚
（谁做了什么、看到了什么、日志里是什么）。紧接着是一道普通的选择题。

## 学员能做什么

与选择题完全相同。场景部分本身不可交互。

## 状态怎么变

无自身状态，判定与展开解释全部由所包裹的选择题负责。

## 数据契约

| 名字 | 用在哪 | 必填 |
|---|---|---|
| `kc-scenario` | 根节点 | 是 |
| `kc-scenario__label` | 顶部的"场景"标签 | 是 |
| `kc-scenario__body` | 情境描述 | 是 |

内部的选择题遵循 `03-quiz.md` 的全部契约。

## 内容规则

- 情境 **2–4 句**，必须具体：给出真实的报错文字、真实的日志行、真实的用户抱怨。
- 报错和日志用**英文原文**，一字不改。
- 情境里要埋进解题所需的线索，**不能靠猜**。
- 一个模块最多一道。全是场景题会让节奏变慢。

## 失败与边界

- 场景块内没有选择题 → 构建失败。
- 场景描述为空 → 构建失败。

## 验收标准

- [ ] 情境读完就知道要判断什么
- [ ] 报错原文与真实运行结果一致
- [ ] 内部选择题的全部验收标准同样通过
