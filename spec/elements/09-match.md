# 拖拽匹配 `kc-match`

## 它是什么

把若干张卡片拖到对应的描述上。用来练"职责归哪个文件"这类对应关系。

## 学员看到什么

上方一排卡片（文件名、组件名），下方若干个靶位，每个靶位上面一句描述、下面一个空位写着"拖到这里"。
最下面两个按钮："对一下"、"重来"。

## 学员能做什么

| 动作 | 结果 |
|---|---|
| 用鼠标把卡片拖到空位 | 空位显示该卡片文字；卡片变暗表示已用 |
| 用手指拖动 | 同上。拖动时手指下跟着一个半透明副本，经过的靶位高亮 |
| 键盘：聚焦卡片按回车选中，再聚焦靶位按回车放下 | 同上 |
| 点"对一下" | 每个已填靶位标为正确或错误；空着的不判 |
| 点"重来" | 全部复位 |

**触屏必须真的能用。** 桌面拖放机制在手机上完全无效，实现必须单独处理触摸。
**键盘路径必须存在**，不能只有拖拽一条路。

## 状态怎么变

| 状态 | 界面 |
|---|---|
| 空 | 靶位显示"拖到这里" |
| 已填未判 | 靶位显示卡片文字 |
| 判定为对 | 靶位标为正确 |
| 判定为错 | 靶位标为错误 |

判定后仍可"重来"。一张卡片同一时刻只能在一个靶位上。

## 数据契约

| 名字 | 用在哪 | 必填 |
|---|---|---|
| `kc-match` | 根节点 | 是 |
| 标识符 | 根节点 | 是 |
| `kc-match__card` | 每张卡片 | 是 |
| `data-kc-key` | 每张卡片 | 是 |
| `kc-match__slot` | 每个靶位 | 是 |
| `data-kc-expect` | 每个靶位 | 是 | 值等于正确卡片的 `data-kc-key` |
| `kc-match__label` | 靶位上的描述 | 是 |
| `kc-match__drop` | 靶位的空位 | 是 |
| `kc-match__check` / `kc-match__reset` | 两个按钮 | 是 |
| `kc-is-placed` / `kc-is-right` / `kc-is-wrong` | 状态 | — |

## 内容规则

- 卡片 **3–5 张**，靶位数量与卡片相同，**一一对应**。
- 描述写成学员会说的话："标题里只有空格的，别让它进来。"
  不要写成"负责输入校验"这种教科书语言。
- 卡片上是**真实的文件名或函数名**，英文原样。

## 失败与边界

- 卡片数与靶位数不等 → 构建失败。
- 某靶位期待的卡片不存在 → 构建失败。
- 两个靶位期待同一张卡片 → 构建失败。
- 脚本未运行 → 卡片与描述照常可读，拖拽无效。

## 验收标准

- [ ] 手机上用手指能完成全流程
- [ ] 键盘能完成全流程
- [ ] 一张卡片不能同时占两个靶位
- [ ] 空着的靶位在"对一下"时不被判错
- [ ] "重来"完全复位
