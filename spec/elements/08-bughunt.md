# 找 bug `kc-bughunt`

## 它是什么

给一段被改坏的代码，让学员**点出有问题的那一行**。全课**至少两处**。

## 学员看到什么

一句引导（"这段代码被人悄悄改坏了，点一下你觉得有问题的那一行"），
下面是带行号的代码，每一行都是可点的。代码下方是一块空的反馈区。

## 学员能做什么

| 动作 | 结果 |
|---|---|
| 点对的那一行 | 该行标为找到；反馈区展开解释：为什么是这一行、会造成什么后果、正确写法是什么；**全部行变为不可点** |
| 点错的行 | 该行短暂标红；反馈区给一句往哪儿想的提示；约 2 秒后自动恢复，可以继续点 |

**点错不惩罚、不计次、不锁定。** 学员可以一直点到找到为止。

## 状态怎么变

| 状态 | 界面 |
|---|---|
| 未找到 | 所有行可点；反馈区空 |
| 刚点错 | 该行短暂标红 + 提示；约 2 秒后自动回到"未找到" |
| 已找到 | 正确行标记为找到；反馈区展开完整解释；全部行不可点（终态） |

## 数据契约

| 名字 | 用在哪 | 必填 |
|---|---|---|
| `kc-bughunt` | 根节点 | 是 |
| `kc-bughunt__code` | 代码容器 | 是 |
| `data-kc-lang` | 代码容器 | 是 | 值恒为 `en` |
| `kc-bughunt__line` | 每一行 | 是 |
| `kc-bughunt__lineno` | 行号 | 是 |
| `data-kc-bug` | 有问题的那一行 | 是 | 全块**有且只有一行**带它 |
| `data-kc-explain` | 有问题的那一行 | 是 | 找到后的完整解释 |
| `data-kc-hint` | 其余每一行 | 是 | 点错时的提示 |
| `kc-bughunt__feedback` | 反馈区 | 是 | **不许带标识符**，靠所属块定位 |

**反馈区一律不带标识符。** 一门课有两处找 bug，写死的标识符必然重复。

## 内容规则

- 代码 **4–8 行**，从真实源码改出来，**只改一处**。
- 那一处改动要是**真实会犯的错**：漏了等待、比较用错、加号写成减号、
  检查了原值而不是处理后的值。不要造语法错误——那种编辑器就报了，学员用不着学。
- 每一行的提示都不一样，**不许四行共用一句"不是这行"**。提示要顺着学员的思路往正确方向引。
- 找到后的解释必须包含：为什么错、会出什么现象、怎么改。
- 代码里出现的函数名、变量名必须是这个项目里真实存在的。

## 失败与边界

- 没有标出问题行，或标了不止一行 → 构建失败。
- 缺解释或某行缺提示 → 构建失败。
- 反馈区带了标识符 → 构建失败。
- 脚本未运行 → 代码照常可读，**解释应当直接可见**。

## 验收标准

- [ ] 有且只有一行是正确答案
- [ ] 点错后约 2 秒自动恢复，可以继续点
- [ ] 找到后不能再点
- [ ] 每一行的错误提示各不相同
- [ ] 同一页面上两处找 bug 互不干扰
- [ ] 键盘能逐行聚焦并触发
