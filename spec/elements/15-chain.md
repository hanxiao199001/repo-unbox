# 箭头流程 `kc-chain`

## 它是什么

一条短的线性流程，横向排列，方块之间用箭头连。比编号步骤卡更紧凑，适合一眼扫完的流程。

## 学员看到什么

横向的若干个小方块，每个里面一个数字加一句短话，方块之间是箭头。
窄屏时改为纵向排列，**箭头方向必须跟着转成向下**。

## 学员能做什么

无交互。

**它和数据流演示的区别**：这个是静态图示，一眼看完；
数据流演示是学员点着一步步走的动画。需要学员参与就用数据流演示，只是标注一下流程就用这个。

## 状态怎么变

无状态。

## 数据契约

| 名字 | 用在哪 | 必填 |
|---|---|---|
| `kc-chain` | 容器 | 是 |
| `kc-chain__step` | 每个方块 | 是 |
| `kc-chain__num` | 方块里的数字 | 是 |
| `kc-chain__arrow` | 箭头 | 是 | 由内容作者写在步骤之间 |

## 内容规则

- **3–5 步**。超过 5 步横向排不下。
- 每步一句短话，越短越好，最好不超过 12 个字。
- 只用于线性流程。有分支的用架构图。

## 失败与边界

- 箭头数量不等于步骤数减一 → 构建时提示。
- 步骤超过 6 个 → 构建时提示，建议改用编号步骤卡。

## 验收标准

- [ ] 窄屏下箭头方向变为向下
- [ ] 横向排列时不出现横向滚动条
