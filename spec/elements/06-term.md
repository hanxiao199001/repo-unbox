# 术语气泡 `kc-term`

## 它是什么

正文里带虚线下划线的词，指上去或点一下弹出一段大白话解释。**这是全课最重要的无障碍设施**——
学员永远不需要离开页面去搜一个词。

## 学员看到什么

正文中的某个词底下有一条虚线。悬停或聚焦时该词变色。弹出的气泡是深色小方块，
里面 1–3 句中文，带一个指向该词的小三角。

## 学员能做什么

| 动作 | 结果 |
|---|---|
| 鼠标移上去 | 气泡出现；移开则消失 |
| 触屏点一下 | 气泡出现；再点一下或点别处则消失 |
| 键盘聚焦 | 气泡出现；移开焦点或按 Esc 则消失 |

**同一时刻最多一个气泡可见。** 打开新的会关掉旧的。

## 气泡的定位

- 默认出现在词的**上方居中**。
- 上方空间不够时**翻到下方**，小三角跟着换方向。
- 左右超出视口时向内收，**不许被裁掉**。
- **气泡不许被任何祖先容器裁切。** 代码对照块这类内部裁剪的容器里也有术语，
  实现上必须让气泡脱离这些容器的裁剪范围。**这是原版最常见的一个缺陷，重写时必须解决。**
- 页面滚动时气泡跟随或直接消失，二选一，但**不许留在原地**。

## 数据契约

| 名字 | 用在哪 | 必填 |
|---|---|---|
| `kc-term` | 带解释的词 | 是 |
| `data-kc-define` | 同上 | 是 | 解释正文 |
| `kc-term__bubble` | 弹出的气泡 | 是 | 由实现创建 |
| `kc-is-open` | 打开状态 | — |

术语必须是**可聚焦**的，并向辅助技术说明它带有一段解释。

## 内容规则

**极度激进地加。只要有 1% 的可能学员不认识，就加。**

- 每个技术术语，在**每个模块内首次出现**时加。同一模块内不重复加。
- 覆盖：英文标识符（`await`、`middleware`、`preventDefault`）、软件名、
  日常开发词（JSON、CLI、flag）、编程概念（函数、变量、对象）、所有缩写。

**英文单词的解释必须给三层**，这是本项目区别于所有英文教程的地方：

1. **直译词义** —— 这个英文词字面什么意思，怎么拆。middle（中间）+ ware（东西）。
2. **在这里指什么** —— 在**这个代码库**里它具体是什么。
3. **国内工程师叫法** —— 中文技术圈实际怎么称呼它。

首次之后，正文用「中文名（English）」的写法，让学员反复见到英文原词。

- 解释 1–3 句，用大白话，能用比喻就用。
- 解释里要教他**怎么用这个词**，不只是它是什么——他将来要用这些词指挥 AI。
- 鼠标指针用手型，**不要用问号型**。问号显得冷冰冰，手型让人想点。

## 失败与边界

- 解释为空 → 构建失败。
- 解释里嵌套了另一个术语标记 → 构建失败（气泡里套气泡无法交互）。
- 脚本未运行 → 虚线下划线仍在，气泡打不开。**必须保证正文本身完整可读**，
  不许把解释藏在只有脚本能打开的地方。

## 验收标准

- [ ] 代码对照块内部的术语，气泡完整可见，没有被裁掉
- [ ] 同时只有一个气泡
- [ ] 触屏上点一下能开、再点能关
- [ ] 键盘能聚焦并打开，Esc 能关
- [ ] 气泡在视口边缘会自动避让
- [ ] 页面滚动后气泡不会孤零零留在原地
- [ ] 每个英文单词的解释都有三层
