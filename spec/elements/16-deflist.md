# 代号表 `kc-deflist`

## 它是什么

一列"代号 + 一句解释"。用于状态码、配置项、权限项、报错这类需要逐条对照的东西。

## 学员看到什么

纵向的若干行，每行左边一个等宽字体的代号（深底浅字），右边一句中文解释。
悬停时该行的边框变色。

## 学员能做什么

- 选中并复制代号（学员会拿去搜或贴给 AI，**必须能复制**）。
- 解释里的术语照常有气泡。

## 状态怎么变

无状态。

## 数据契约

| 名字 | 用在哪 | 必填 |
|---|---|---|
| `kc-deflist` | 容器 | 是 |
| `kc-deflist__row` | 每一行 | 是 |
| `kc-deflist__key` | 代号 | 是 |
| `data-kc-lang` | 代号 | 是 | 值恒为 `en` |
| `kc-deflist__value` | 解释 | 是 |

## 内容规则

- **3–6 行**。
- 代号是**真实的英文原文**：状态码、报错、配置键名，一字不改。
- 解释里要说清楚"这意味着什么"和"你该做什么"，不只是字面翻译。
- 用来放课末"你最可能撞上的报错"时，每条要包含：报错原文、中文意思、通常什么原因、
  该对 AI 怎么说。
- **报错原文必须是真的跑出来过的**，并且要说清楚在什么条件下才会出现。
  不要写成"一定会失败"——那对一半的读者是假的。

## 失败与边界

- 代号区域没有标为英文 → 构建失败（中文断行规则会作用在报错文本上）。
- 行数超过 8 → 构建时提示。

## 验收标准

- [ ] 代号可以完整选中复制，与源文一致
- [ ] 长代号在窄屏下折行而不撑破容器
- [ ] 代号区域内不生效中文排版规则
