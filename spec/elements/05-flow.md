# 数据流演示 `kc-flow`

## 它是什么

一排角色，数据在他们之间一步一步移动。学员自己点"下一步"控制节奏。**全课至少出现一次。**

## 学员看到什么

横向排开的若干个角色，每个是一个图标加一个名字。下方一行文字说明当前这一步在做什么，
再下面两个按钮："下一步"、"重来"，以及进度"第 3 步 / 共 7 步"。

初始时说明文字是一句引导语，没有角色被高亮。

## 学员能做什么

| 动作 | 结果 |
|---|---|
| 点"下一步" | 推进一步：当前步骤的角色被高亮；如果这一步涉及传递，一个小方块从起点角色飞到终点角色；说明文字换成这一步的描述；进度 +1 |
| 点"重来" | 全部高亮取消，说明文字恢复引导语，进度归零 |

到最后一步后再点"下一步"无效果，不报错。

## 状态怎么变

一个游标：当前第几步。每一步描述四件事：

1. 高亮哪个角色
2. 这一步的说明文字
3. 是否有数据包在飞
4. 如果有，从哪个角色飞到哪个角色

高亮是**排他的**：任何时刻最多一个角色处于高亮。

数据包的飞行是一次性动画，约 0.8 秒，飞完消失。**必须按实际元素位置计算轨迹**，
不能写死坐标——窄屏下角色会换行排列，写死的轨迹会飞到屏幕外。

## 数据契约

| 名字 | 用在哪 | 必填 |
|---|---|---|
| `kc-flow` | 根节点 | 是 |
| `data-kc-steps` | 根节点 | 是 | 步骤序列，见下 |
| `kc-flow__actor` | 每个角色 | 是 |
| 角色标识符 | 每个角色 | 是 | **整页唯一** |
| `kc-flow__icon` / `kc-flow__name` | 角色的图标与名字 | 是 |
| `kc-flow__packet` | 飞行的数据包 | 是 |
| `kc-flow__caption` | 说明文字 | 是 |
| `kc-flow__next` / `kc-flow__reset` | 两个按钮 | 是 |
| `kc-flow__progress` | 进度提示 | 是 |

**步骤序列**里每一步含：高亮的角色标识符、说明文字、是否传递、起点标识符、终点标识符。

**角色标识符必须整页唯一。** 两个模块各有一个数据流演示、角色都叫"第一个"，
就是重复标识符，构建会失败。标识符中间要放模块特有的部分。

## 内容规则

- 角色 **3–5 个**。多于 5 个横向排不下，学员也跟不住。
- 步骤 **5–8 步**。
- 每步说明一句话，**说清楚"发生了什么"而不是"调用了什么"**。
- 说明文字里**不许出现英文单引号**——步骤序列的承载格式对它敏感，
  一个撇号就会让整个动画静默失效。需要引号时用中文引号。
- 主线要对应学员真实做过的动作，从他点的那一下开始。

## 失败与边界

- 步骤序列解析失败 → 构建失败，并指出是哪个块。**这是最容易静默失效的地方**，
  必须硬失败，不许悄悄不动。
- 步骤引用了不存在的角色标识符 → 构建失败。
- 角色标识符重复 → 构建失败。
- 步骤序列为空 → 构建失败。
- 脚本未运行 → 角色和名字照常可见，说明文字应显示引导语，按钮无效。

## 验收标准

- [ ] 任意时刻最多一个角色高亮
- [ ] 窄屏下角色换行后，数据包仍然飞在正确的两点之间
- [ ] 走到最后再点"下一步"无异常
- [ ] "重来"完全复原
- [ ] 进度提示与实际步数一致
- [ ] 步骤序列里带撇号时，构建报错而不是页面静默失效
