# 规格：课程页面

这里是**功能规格**，不是实现文档。每一份都描述"学员看到什么、能做什么、状态怎么变"，
不描述"用什么属性、哪个函数、怎么写"。

读者假设：一个**没见过原版**的前端工程师，只看这些文档就能从零实现出来，
实现方式（框架、CSS 方案、打包器）由实现者自己定。

## 目录

| 文件 | 内容 |
|---|---|
| `page-shell.md` | 页面骨架：一门课由什么组成，模块和屏怎么嵌套 |
| `navigation.md` | 顶部导航、进度条、模块圆点、键盘操作 |
| `typography-zh.md` | 中文排版要求（原版没有，是这一版新增的硬要求） |
| `elements/*.md` | 18 种交互元素，一种一份 |

## 命名约定

原版的名字全部作废，这里重新定义。**实现时必须用这套名字**，不要沿用任何旧名。

| 类别 | 形式 | 例子 |
|---|---|---|
| 元素根节点的名字 | `kc-<元素>` | `kc-quiz` |
| 元素内部部件 | `kc-<元素>__<部件>` | `kc-quiz__option` |
| 状态标记 | `kc-is-<状态>` | `kc-is-selected` |
| 数据属性 | `data-kc-<名字>` | `data-kc-answer` |
| 标识符 | 由内容作者提供，**整个页面内全局唯一** | `kc-quiz-m3` |

`kc` 取自"课程"。前缀存在的唯一目的，是保证这套名字和任何既有实现都不会撞。

**规格里出现的所有名字都是数据契约**：内容作者按它写 HTML，实现者按它接管行为。
两边都不许自己改名。

## 全局约束

1. **零网络请求。** 一门构建好的课程必须能在断网、离线、无 CDN 的环境里完整打开。
   字体、脚本、样式全部随课程分发。
2. **不依赖构建期 JavaScript 框架。** 产物是可以直接双击打开的页面。
3. **代码原文一字不改。** 凡是展示源代码的地方，展示的必须是源文件里连续若干行的逐字复制。
4. **中英文分区。** 页面主语言是中文；凡内容为英文的部件（代码、报错、终端输出、
   单独出现的文件名与标识符）必须显式标注为英文，否则中文断行规则会作用在它们身上。
5. **键盘可达。** 每一个可点击的东西都必须能用键盘到达并触发。
6. **无声失败是最严重的缺陷。** 任何元素在数据缺失或格式错误时，
   必须在页面上留下可见痕迹，不许静默地什么都不显示。

## 每份元素规格的固定结构

1. **它是什么** —— 一句话
2. **学员看到什么** —— 静止状态下屏幕上有什么
3. **学员能做什么** —— 可交互的动作，逐条列
4. **状态怎么变** —— 状态机：有哪些状态、什么触发迁移、每个状态下界面是什么样
5. **数据契约** —— 需要哪些名字、哪些数据属性、各自的取值范围和必填性
6. **内容规则** —— 写内容的人必须遵守的约束（数量、长度、语言）
7. **失败与边界** —— 数据不对时该怎么表现
8. **验收标准** —— 可逐条勾的清单

## 这批规格与旧实现的关系

旧实现（`.legacy/`）**不是参考答案**。它有几处已知缺陷被本规格明确改掉：

- 元素范例里带写死的标识符，同一元素用两次就撞名
- 部分元素的状态迁移只在实现里存在，从未被写下来
- 完全没有中文排版规定，中文正文沿用了为拉丁字母调的行高与字距

遇到规格与旧实现不一致的地方，**以规格为准**。
