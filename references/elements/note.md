# 提示框 `kc-note`

从正文里跳出来的一个方块，放一条通用原理或一句警告。标记“原来如此”的时刻。

```html
<div class="kc-note" data-kc-tone="insight">
  <span class="kc-note__icon">✦</span>
  <p class="kc-note__title">关注点分离</p>
  <p class="kc-note__body">每一块只管一件事。页面只管画，服务器只管分诊，只有一个文件碰硬盘——出问题的时候你才知道该去哪找。</p>
</div>
```

## 三种语气

| `data-kc-tone` | 图标建议 | 用在什么时候 |
|---|---|---|
| `insight` | `✦` | 通用的计算机原理，值得记住的那种 |
| `info` | `ℹ` | 知道了更好、不知道也不影响的补充 |
| `warning` | `⚠` | 常见错误、容易踩的坑 |

**三种语气的图标必须不一样**——灰度截图里要能靠图标分辨，不能只靠颜色。

## 数据契约

| 名字 | 用在哪 | 必填 |
|---|---|---|
| `kc-note` + `data-kc-tone` | 根节点 | 是 |
| `kc-note__icon` | 图标 | 是 |
| `kc-note__title` | 小标题 | 是 |
| `kc-note__body` | 正文 | 是 |

## 内容规则

- **一个模块最多 2 个**。满屏提示框等于没有提示框。
- 内容必须是**跳出这个项目也成立的通用原理**，例如“关注点分离”“单一出口”。
  只在本项目成立的细节写正文里，不要放提示框。
- 正文 1–3 句。
- 如果这条原理有工程界的通用名字，**把名字写出来**——学员将来要用这个词去问 AI。

## 失败与边界

- 语气不在三个值里、缺图标/标题/正文 → 页面留红色痕迹，构建失败。
- 一个模块超过 2 个 → 构建时提示，不失败。
