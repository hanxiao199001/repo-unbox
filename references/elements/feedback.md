# 这里没看懂 `kc-feedback`

每一屏右上角一个小按钮。学员看不懂时点一下，记在他自己的浏览器里；课末一个按钮
把全部记录导出成 JSON。**不联网、不上报、不判分。**

## 你什么都不用写

按钮由 `scripts/build.mjs` 注入到每一个 `kc-screen`，课末那一块在 `_footer.html` 里，
两样都是构建脚本的地盘。**不要在模块 HTML 里手写它们**，写了会重复。

构建输出里会有一行 `“这里没看懂” buttons: N injected (one per screen)`，
N 应当等于你这门课的总屏数。`scripts/validate.mjs` 会再查一遍：有一屏漏了就失败。

## 它记什么

点一下写进一条记录，含：模块标识符、模块编号、模块标题、这一屏在模块里的序号、
屏标题、那一句话（可以为空）、ISO 时间戳。

再点一次撤销。那一句话是**可选的**——记录在点下按钮的那一刻就已经写好了，
学员写到一半关掉页面也不影响。

## 这条对你写内容的唯一影响

**屏标题就是学员反馈里唯一能认出这一屏的东西。** 一屏没有 `kc-screen__title`，
导出的记录里就只剩「模块 3 第 2 屏」，你事后根本不知道他卡在哪。

所以：**凡是可能让人卡住的屏，都给它一个具体的标题。**
「检查一下」这种标题在三个模块里各出现一次，等于没有标题。

## 数据契约（实现用，写内容的人不用管）

| 名字 | 用在哪 |
|---|---|
| `kc-feedback` | 每一屏的按钮，构建注入 |
| `kc-feedback__panel` / `kc-feedback__note` | 输入区与那一句话，实现创建 |
| `kc-is-marked` | 已标记的按钮 |
| `kc-feedback-export` 及其 `__count` / `__button` / `__clear` / `__fallback` | 课末那一块，在 `_footer.html` 里 |

## 失败与边界

- 有 `kc-screen` 没有按钮、或课末那一块缺件 → 构建失败。
- 本机存储不可用 → 静默降级：还能点、还能导出，只是刷新不保留。不报错。
- 浏览器拦住下载 → JSON 显示在兜底文本框里让学员自己复制，绝不会什么都不发生。
- 脚本未运行 → 按钮和课末那一块照常显示，点不动，正文完全不受影响。
