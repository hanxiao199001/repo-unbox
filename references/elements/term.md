# 术语气泡 `kc-term`

正文里带虚线下划线的词，指上去或点一下弹出大白话解释。
**全课最重要的无障碍设施——学员永远不需要离开页面去搜一个词。**

```html
请求先经过<span class="kc-term" data-kc-define="middle（中间）+ ware（东西），夹在中间的那层东西。在这个项目里，它是请求到达路由之前依次经过的一串检查函数。国内叫中间件，口语里也直接说 middleware。">中间件</span>，再进到路由里。
```

气泡由实现创建并挂在页面末尾，**你只写这一个 `<span>`**。

## 数据契约

| 名字 | 用在哪 | 必填 |
|---|---|---|
| `kc-term` | 带解释的词 | 是 |
| `data-kc-define` | 同上，解释正文 | 是 |

## 内容规则

**极度激进地加。只要有 1% 的可能学员不认识，就加。**

- 每个技术术语，在**每个模块内首次出现**时加；同一模块内不重复加。
- 覆盖：英文标识符（`await`、`middleware`、`preventDefault`）、软件名、
  日常开发词（JSON、CLI、flag）、编程概念（函数、变量、对象）、所有缩写。

**英文单词的解释必须给三层**，这是本项目区别于所有英文教程的地方：

1. **直译词义** —— 这个英文词字面什么意思，怎么拆。middle（中间）+ ware（东西）。
2. **在这里指什么** —— 在**这个代码库**里它具体是什么。
3. **国内工程师叫法** —— 中文技术圈实际怎么称呼它。

首次之后，正文用「中文名（English）」的写法，让学员反复见到英文原词。

- 解释 1–3 句，用大白话，能用比喻就用。
- 解释里要教他**怎么用这个词**——他将来要用这些词指挥 AI。
- 解释里**不许再嵌套一个 `kc-term`**，气泡里套气泡无法交互。

## 失败与边界

- 解释为空、或嵌套了另一个术语 → 该词原地标红并挂警示号，点不开，构建失败。
- 脚本未运行 → 虚线下划线仍在，正文完整可读，气泡打不开。
