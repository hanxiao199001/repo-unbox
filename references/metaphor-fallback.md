# 比喻备用表

> **什么时候读：** **只有当目标项目自己的题材撑不起某个概念时**才读这一份。
> 先别打开——先做下面这件事。

## 先做这件事

在写任何比喻之前，把目标仓库自己的名词列出来三个。看 README 的第一段、
看代码里反复出现的词、看它给自己起的名字。

- 一个深空电台主题的留言板：**信号、频率、接收站、呼号、发射**
- 一个音乐播放器：**唱片、播放列表、音轨、试听**
- 一个待办清单：**清单、勾掉、截止日期**

**从项目题材里长出来的比喻，学员一边学比喻一边熟悉这个项目，是双倍的收益。**
下面这张表只是兜底：项目题材实在接不上某个概念时，才从这里挑一个。

一门课里 5 个模块，**至少 3 个的比喻应该长在项目自己的题材上**。
`scripts/validate.mjs` 会数一遍，不够就 WARN（警告，不失败）——
因为确实存在题材本身就很单薄的项目（一个通用的 CRUD 示例就没什么可借的）。

## 表

`data-kc-metaphor` 里就写反引号里那个短名。

| 概念 | 短名 | 怎么讲 |
|---|---|---|
| 服务器 / 客户端 | `快递驿站` | 你不进仓库，你在窗口报单号，里面的人帮你取 |
| 中间件链 | `地铁进站` | 安检机 → 闸机 → 站台，每一关都能把你拦下来 |
| 路由 | `医院挂号分诊台` | 按你说的科室，把你指到对应诊室 |
| API 接口 | `食堂打饭窗口` | 只能点菜单上有的，怎么做的你不用管 |
| 认证 / 权限 | `小区门禁` | 卡对了才放行，跟你是谁没关系，跟你有没有卡有关系 |
| 缓存 | `手机里存过的外卖地址` | 不用每次重新输 |
| 内存 vs 硬盘 | `白板与档案柜` | 白板写得快、停电就没；档案柜慢，但明天还在 |
| 异步等待 | `外卖骑手接单` | 接了单不站着等出餐，先去接别的，好了再回来取 |
| 报错状态码 | `自助取件柜的提示` | 取件码错了、格子空了、机器坏了——三件完全不同的事 |

## 明令禁止

- **餐厅 / 厨房比喻**（一律不用）
- **美式生活场景**：棒球、感恩节、drive-thru、邮筒投递、图书馆卡片目录、机场值机、
  美式银行柜台——学员没有这些心理图像，比喻反而成了第二道障碍
- 任何需要先解释比喻本身的比喻
