02

谁来接这一单

大门口不干活，它只负责把你指到对的柜台。

大门口只做一件事

上一模块里，请求飞到了 server.js。你可能以为它就是那个“干活的”。其实正相反——它一件活都不干。

它像医院的挂号分诊台：你说哪儿不舒服，它给你指一个诊室。它不给你看病，它只负责别把你指错地方。

这个动作在工程界有个词，叫路由。一条路由就是一句约定：“凡是走这个地址、用这个动作来的，都交给某某处理。”

src/server.js:26-34

// Serve the browser client from public/
app.use(express.static(path.join(__dirname, '..', 'public')));

// Mount the todo routes under /api/todos
app.use('/api/todos', todosRouter);

app.get('/api/health', (req, res) => {
  res.json({ status: 'ok', count: store.all().length, uptime: process.uptime() });
});

原作者的注释：把 public 文件夹里的东西直接端出去。

static 的意思是“现成的，拿了就走”。你打开网页时下载的 index.html 就是从这一行出去的。

原作者的注释：把待办相关的那一堆路由挂在 /api/todos 底下。

这一行是本模块的核心。挂的意思是：凡是地址以 /api/todos 开头的，全部转给 todosRouter，大门口自己不看内容。

这里是唯一一条大门口自己接的路——一个健康检查。

它回一个小对象，告诉你服务活着、现在有几条待办、已经跑了多久。你把 /api/health 输进浏览器就能看到。

✦

顺序即规则

这几行是从上往下依次生效的。谁写在前面谁先有机会接住请求，一旦被接住，后面的就轮不到了。很多“为什么我的接口没反应”，答案就是它被写在了另一条更宽的规则后面。

进站要过几道关

请求到达柜台之前，先被几个人依次摸了一遍。

中间那一层

上一模块留了一个尾巴：那一行里，validateCreate 排在真正干活的函数前面。它是什么？

它是中间件。

这就像坐地铁进站：安检机 → 闸机 → 站台。每一关都能把你拦下来，也都能放你过去。放过去了，你就到下一关；被拦下来，你根本走不到站台。

请求也是一样。它到达待办柜台之前，已经被好几个人依次摸过一遍了。

第二关：每一次请求都被记了一笔

这段是项目自己写的一个中间件。它谁也不拦，只是把每次请求记下来。

src/server.js:16-24

// Log every request: method, path, and how long it took
app.use((req, res, next) => {
  const startedAt = Date.now();
  res.on('finish', () => {
    const ms = Date.now() - startedAt;
    console.log(`${req.method} ${req.originalUrl} -> ${res.statusCode} (${ms}ms)`);
  });
  next();
});

原作者的注释：记下每个请求的动作、路径和耗时。

app.use 就是“往关卡链上加一道”。这道关对所有请求生效。

先记一下现在几点。

给“回复发完了”这件事挂一个监听。finish 那一刻才知道这次总共花了多久。

用结束时间减开始时间，得到毫秒数。

打印一行。你在终端里看到的 POST /api/todos -> 201 (3ms) 就是这一行印的。

监听挂完了。

这一行不能少。next() 就是“放行，交给下一关”。忘了写，请求会一直卡在这里，页面转圈转到超时。

这道关到此结束。

⚠

最常见的一个坑

中间件里忘了调 next()，请求既不报错也不返回，页面就一直转圈。这类问题不会打印任何东西，因为程序并没有“出错”，它只是在等一个永远不来的信号。

// Guards POST /api/todos — a new todo must have a usable title.
export function validateCreate(req, res, next) {
  const title = cleanTitle(req.body?.title);
  if (title === null) {
    return next(new HttpError(400, 'title is required', {
      field: 'title',
      rule: `non-empty string, at most ${MAX_TITLE_LENGTH} characters`,

  req.body.title = title;
  next();

原作者的注释：守住新建这条路，新待办必须有一个能用的标题。

洗出来是 null，说明这个标题不能用。

拦下来，报 400。400 的意思是“你发来的东西不对”，不是“服务器坏了”。

顺便告诉对方是哪个字段出的问题。

以及这个字段的规矩是什么。这两行让报错变得可以照着改，而不只是“不行”。

拦截结束，注意开头那个 return——没有它，代码会继续往下跑。

这一段的括号收尾。

04

东西到底存在哪

为什么刷新还在，关机重启也还在。

两个地方，性格完全不同

“数据存在哪”这个问题，在这个项目里有两个答案，而且两个都对。

一个是内存，一个是硬盘。它们的关系就像办公室里的白板和档案柜：白板写起来快，一擦就没，停电也没；档案柜慢，但明天来了它还在。

这个项目两样都用：白板上放一份随时能看的副本，档案柜里放那份说了算的。

◧

白板

程序里那个叫 todos 的数组。查询待办时直接从它读，不碰硬盘，所以快。服务一停，它就没了。

◨

档案柜

data/todos.json 这个文件。每次有改动就重写一遍。你关掉终端、重启电脑，它都还在。

◩

谁说了算

档案柜。程序启动时先把文件读进白板，之后每次改动再写回去。文件是唯一的真相。

原作者自己写了答案

这四行里有两行是注释。它们是整个项目里最值钱的两句话——写代码的人在解释他为什么这么设计。

src/store.js:9-12

// In-memory cache of every todo. The JSON file on disk is the source of truth,
// but we only read it once at boot and write it back after each change.
let todos = [];
let writeQueue = Promise.resolve();

原作者的第一句：这是所有待办的缓存，硬盘上那个 JSON 文件才是真相源。

第二句是关键：文件只在启动时读一次，之后每次改动写回去。所以查询快，因为根本不读盘。

白板本身，一开始是空的。

一个排队用的东西，下一屏专门讲它为什么必须存在。

src/store.js:14-21

async function persist() {
  // Chain writes so two rapid requests can never interleave and corrupt the file.
  writeQueue = writeQueue.then(async () => {
    await fs.mkdir(path.dirname(DATA_FILE), { recursive: true });
    await fs.writeFile(DATA_FILE, JSON.stringify(todos, null, 2), 'utf8');
  });
  return writeQueue;
}

persist 的意思是“把它留住”，也就是写进硬盘。

原作者的注释：把写盘排成一队，两个请求挨得再近也不会交叉着写、把文件写坏。

排队的做法：新的写盘接在上一次的后面，等前一个写完才轮到它。

先确保放文件的那个文件夹存在，不存在就建出来。

真正写盘的一行。第三个参数 2 是缩进空格数——所以你打开 todos.json 看到的是排好版的，不是挤成一行。

这一次的写盘结束。

把这一队还回去，好让调用者能 await 它。

函数收尾。

✦

单一出口（single writer）

整个项目里，只有 persist 这一个函数会写那个文件。想改存储方式——换成数据库、加个备份——只需要动这一处。碰同一份数据的地方越少，出问题时要查的地方就越少。

05

出错的时候看哪儿

看懂那行英文，比会写代码更早派上用场。

所有的错都走同一个出口

前面几个模块里，你见过好几次 next(err)。它们最后都去了同一个地方。

这就像小区里的自助取件柜：取件码错了、格子是空的、机器本身坏了——三件完全不同的事，但柜子上只有一块屏幕在提示你。区别在于它显示哪一句。

src/middleware/errorHandler.js:15-24

// Express recognises this as the error handler because it takes FOUR arguments.
// Every next(err) anywhere in the app ends up here.
export function errorHandler(err, req, res, next) {
  const status = err.status || 500;
  if (status >= 500) console.error(err);
  res.status(status).json({
    error: err.message || 'Internal Server Error',
    details: err.details,
  });
}

原作者的第一句注释，也是这段最反直觉的一点：框架靠参数个数认出它是错误处理器。四个参数，不是三个。

第二句：项目里任何地方的 next(err)，最后都到这儿。

函数名 errorHandler，四个参数第一个就是错误本身。

错误自己带了状态码就用它，没带就当作 500。这个 || 读作“或者”，前面没有就用后面的。

只有 500 这类“我们自己的锅”才往终端打完整堆栈。用户输错了不值得刷屏。

按这个状态码回复。

把人能读的那句话放进 error 字段。页面上那行红字就是它。

附带更细的信息，比如是哪个字段不合格。第三模块的 400 就带了这个。

回复内容结束。

函数结束。整个项目所有的错误，出口只有这一个。

⚠

四个参数不是随便写的

把最后那个 next 删掉，函数只剩三个参数，框架就会把它当成普通中间件，所有错误再也进不来。页面会一直转圈，终端里什么都不打印。这是这个项目最难查的一处坑。

让 AI 帮你跑起来时，你可以这样说

下面三句可以直接复制。中文在上，英文在下——英文那句是你将来在英文界面里要用的原话。

1

把项目跑起来

2

加一个功能

“给待办加一个截止日期字段。在 validate.js 里校验它，在 store.js 的 create 里保存它，不合格时返回 400。”
Add a due date field to todos. Validate it in validate.js, save it in store.js create, and return 400 when it is invalid.

3

修一个报错

“我跑起来时终端报 EADDRINUSE，端口 3000 被占了。告诉我怎么找到占用它的进程，以及怎么改成从环境变量读端口。”
I get EADDRINUSE on port 3000. Show me how to find the process using it, and how to read the port from an environment variable instead.

你最可能撞上的报错

下面四条都是这个项目真的会抛出来的原文。左边一字不改，右边是中文意思和该怎么办。

Error: listen EADDRINUSE: address already in use :::3000

3000 这个端口已经被占了，通常是你上一个终端还开着。关掉它，或者启动时写 PORT=3001 npm start。对 AI 可以说：“把端口改成从 PORT 环境变量读。”

{"error":"title is required","details":{"field":"title","rule":"non-empty string, at most 200 characters"}}

这是第三模块那道校验关回的 400。它已经把哪个字段、什么规矩都告诉你了。这是一个“好报错”的样子：照着它就能改。

{"error":"todo not found"}

配合 404 出现。要么 id 拼错了，要么这条待办已经被删掉了。先在 data/todos.json 里搜一下这个 id 还在不在。

SyntaxError: Unexpected token } in JSON at position 42

读 data/todos.json 时发现文件内容不是合法 JSON，通常是手动改坏了。position 42 是出问题的字符位置。对 AI 说：“帮我把 data/todos.json 的格式修好。”

最后检查一下

页面上出现一行红字写着 Internal Server Error，你下一步去哪儿看？

有人觉得 errorHandler 最后那个 next 从来没用过，把它删了。结果是什么？

你朋友看到页面上一行红字就慌了。用不超过三句话告诉他：怎么先分清这是谁的问题。

  • 说出了 status code 这个英文原词，或者至少说出了“状态码”并举了一个具体数字
  • 讲清楚了 400 和 500 的区别是“你发的东西不对”和“服务器自己出事了”
  • 说到了 500 要去终端看，而不是在浏览器里干瞪眼
