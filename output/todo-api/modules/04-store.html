东西到底存在哪

为什么刷新还在，关机重启也还在。

两个地方，性格完全不同

“数据存在哪”这个问题，在这个项目里有两个答案，而且两个都对。

一个是内存，一个是硬盘。它们的关系就像办公室里的白板和档案柜：白板写起来快，一擦就没，停电也没；档案柜慢，但明天来了它还在。

这个项目两样都用：白板上放一份随时能看的副本，档案柜里放那份说了算的。

◧

白板

程序里那个叫 todos 的数组。查询待办时直接从它读，不碰硬盘，所以快。服务一停，它就没了。

◨

档案柜

data/todos.json 这个文件。每次有改动就重写一遍。你关掉终端、重启电脑，它都还在。

◩

谁说了算

档案柜。程序启动时先把文件读进白板，之后每次改动再写回去。文件是唯一的真相。

原作者自己写了答案

这四行里有两行是注释。它们是整个项目里最值钱的两句话——写代码的人在解释他为什么这么设计。

src/store.js:9-12

// In-memory cache of every todo. The JSON file on disk is the source of truth,
// but we only read it once at boot and write it back after each change.
let todos = [];
let writeQueue = Promise.resolve();

原作者的第一句：这是所有待办的缓存，硬盘上那个 JSON 文件才是真相源。

第二句是关键：文件只在启动时读一次，之后每次改动写回去。所以查询快，因为根本不读盘。

白板本身，一开始是空的。

一个排队用的东西，下一屏专门讲它为什么必须存在。

src/store.js:14-21

async function persist() {
  // Chain writes so two rapid requests can never interleave and corrupt the file.
  writeQueue = writeQueue.then(async () => {
    await fs.mkdir(path.dirname(DATA_FILE), { recursive: true });
    await fs.writeFile(DATA_FILE, JSON.stringify(todos, null, 2), 'utf8');
  });
  return writeQueue;
}

persist 的意思是“把它留住”，也就是写进硬盘。

原作者的注释：把写盘排成一队，两个请求挨得再近也不会交叉着写、把文件写坏。

排队的做法：新的写盘接在上一次的后面，等前一个写完才轮到它。

先确保放文件的那个文件夹存在，不存在就建出来。

真正写盘的一行。第三个参数 2 是缩进空格数——所以你打开 todos.json 看到的是排好版的，不是挤成一行。

这一次的写盘结束。

把这一队还回去，好让调用者能 await 它。

函数收尾。

✦

单一出口（single writer）

整个项目里，只有 persist 这一个函数会写那个文件。想改存储方式——换成数据库、加个备份——只需要动这一处。碰同一份数据的地方越少，出问题时要查的地方就越少。
