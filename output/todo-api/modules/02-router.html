谁来接这一单

大门口不干活，它只负责把你指到对的柜台。

大门口只做一件事

上一模块里，请求飞到了 server.js。你可能以为它就是那个“干活的”。其实正相反——它一件活都不干。

它像医院的挂号分诊台：你说哪儿不舒服，它给你指一个诊室。它不给你看病，它只负责别把你指错地方。

这个动作在工程界有个词，叫路由。一条路由就是一句约定：“凡是走这个地址、用这个动作来的，都交给某某处理。”

src/server.js:26-34

// Serve the browser client from public/
app.use(express.static(path.join(__dirname, '..', 'public')));

// Mount the todo routes under /api/todos
app.use('/api/todos', todosRouter);

app.get('/api/health', (req, res) => {
  res.json({ status: 'ok', count: store.all().length, uptime: process.uptime() });
});

原作者的注释：把 public 文件夹里的东西直接端出去。

static 的意思是“现成的，拿了就走”。你打开网页时下载的 index.html 就是从这一行出去的。

原作者的注释：把待办相关的那一堆路由挂在 /api/todos 底下。

这一行是本模块的核心。挂的意思是：凡是地址以 /api/todos 开头的，全部转给 todosRouter，大门口自己不看内容。

这里是唯一一条大门口自己接的路——一个健康检查。

它回一个小对象，告诉你服务活着、现在有几条待办、已经跑了多久。你把 /api/health 输进浏览器就能看到。

✦

顺序即规则

这几行是从上往下依次生效的。谁写在前面谁先有机会接住请求，一旦被接住，后面的就轮不到了。很多“为什么我的接口没反应”，答案就是它被写在了另一条更宽的规则后面。

柜台里发生了什么

被指到待办柜台之后，真正处理“新建一条”的是下面这九行。

src/routes/todos.js:22-30

// POST /api/todos
router.post('/', validateCreate, async (req, res, next) => {
  try {
    const todo = await store.create({ title: req.body.title });
    res.status(201).json(todo);
  } catch (err) {
    next(err);
  }
});

原作者的注释，写清楚这一段管的是哪个地址、哪个动作。

注意这一行有两个东西排在一起：先是 validateCreate，然后才是真正干活的那个函数。前者是门卫，下一个模块专门讲它。

try 的意思是“下面可能出事”。

await 是“等一下”。写硬盘要花时间，这一行会等它写完再往下走。req.body 就是你发来的那个 JSON。

写成功了就回一个 201。201 不是随便挑的数字，它专门表示“新东西已经建出来了”。

出事了掉到这里。

next(err) 的意思是“我处理不了，往下传”。传到哪儿，第五个模块揭晓。

这一段到此结束。

检查一下

server.js 在这个项目里干的是什么活？

你想加一个“把所有已完成的待办一次性清空”的功能，你会对 AI 说：请改哪个文件？

新建成功时返回 201 而不是 200，多告诉了调用方什么？

你朋友问你“路由到底是个啥”。用不超过三句话讲给他听，不许用“映射”“分发”这类词。

  • 说出了这个概念的英文原词 route，并且知道它字面是“路线”
  • 讲清楚了它是“把某个地址交给某段代码去处理”这件事，而不是背了一句定义
  • 用了一个你自己的比喻，没有直接搬“分诊台”
