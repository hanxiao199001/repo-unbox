你点的那一下

从你敲的三个字，一路追到硬盘上的那个文件。

先做一件你已经做过的事

页面上有一个输入框，你在里面打了“买牛奶”，按了旁边的“Add”。列表里多出来一条。你刷新页面，它还在。

这一门课要讲的全部内容，就是这三句话背后发生的事。不是从“什么是服务器”开始讲，是从你的手指开始讲。

你已经知道结局了——那条待办确实出现了。悬念不在“会发生什么”，在“凭什么”。

✦

关注点分离（separation of concerns）

这个项目把“画页面”“接请求”“存数据”拆给了三个不同的文件。拆开的好处不是好看，是出问题时你知道该先打开哪一个。这是整门课最值钱的一句话，工程界管它叫关注点分离。

这个项目里有谁

先认四个主要的，各管一摊。名字全是英文，你会反复见到它们，所以现在就认脸。

P

public/index.html

你眼睛看到的那个页面。它收你敲的字，也负责把列表画出来。它不存东西，关掉标签页什么都不剩。

S

src/server.js

大门口。所有请求先到它这儿，它决定这一单该交给谁。它自己什么活都不干。

R

src/routes/todos.js

专门处理待办这一摊的柜台：新增、查询、修改、删除，四个动作都在这里接单。

T

src/store.js

只有它碰硬盘。数据不对、刷新之后没了，第一个来找它。

src/ 服务器端的代码全在这儿，外面那些是配置和说明。
server.js 大门口——启动程序，决定每种请求交给谁。
store.js 只有它碰硬盘。
public/ 浏览器直接下载的东西都在这儿，不经过任何加工。
index.html 页面本身，连样式和脚本都写在里面，一个文件就是整个前端。

点下去之后，这句话走了哪条路

点“下一步”，跟着“买牛奶”走一遍。这条路你后面四个模块都会反复走，先有个整体印象。

🧑你
▤index.html
▣server.js
◫todos.js
▦store.js

点“下一步”，跟着“买牛奶”这三个字走一遍。

这就像小区门口的快递驿站：你不进仓库，你在窗口说要什么，里面的人帮你去取。页面就是那个窗口，它自己一件货都没有。

页面这一头，代码长什么样

下面这段是你按下 Add 时真正跑起来的代码。左边是原文，右边一行一行讲。

public/index.html:83-93

    form.addEventListener('submit', async (event) => {
      event.preventDefault();
      const title = new FormData(form).get('title');
      try {
        await api('/api/todos', { method: 'POST', body: JSON.stringify({ title }) });
        form.reset();
        refresh();
      } catch (err) {
        errorBox.textContent = err.message;
      }
    });

给表单挂一个“有人提交了”的监听。submit 就是你按 Add 的那一下。

preventDefault 挡掉浏览器的默认反应。不写这一行，整个页面会刷新一次。

把输入框里的字取出来，存进 title 这个变量。title 就是“标题”。

下面这段用 try 包起来，意思是“下面可能会出事，出事了别把整个页面搞崩”。

这一行才是真的往外发。POST 表示“我要新建一个”，JSON.stringify 把对象变成一串能在网线上传的字。

发完就把输入框清空。

这一行是本模块最重要的一行。页面没有自己把新待办画上去，它调用 refresh，重新问了服务器一遍。

万一上面哪一步出事了，掉到这里来。

把错误的文字显示在页面上那行红字里。

ℹ

为什么不自己画

自己画一条，页面上的列表就可能和服务器上的真实数据对不上。重新问一遍虽然多花一次往返，但屏幕上显示的永远是真的。这个取舍叫“以服务器为准”。

检查一下

你点了 Add 之后，页面上那条新待办是怎么出现的？

同事说“我加的待办刷新一下就没了”，你第一个打开哪个文件？

用你自己的话说一遍：你打了“买牛奶”并按下 Add 之后，这三个字依次经过了哪些文件？最后停在哪儿？

  • 说出了 index.html 先把字收起来，并且提到它挡掉了整页刷新
  • 提到请求走的是 POST /api/todos 这条路
  • 说清楚了只有 store.js 会往硬盘上写，写的是 todos.json
  • 说到了页面最后是重新问了一遍，而不是自己把那一条画上去
