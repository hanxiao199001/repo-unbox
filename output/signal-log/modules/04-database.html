日志本记在哪一页

留言存进 SQLite，信号强度是算出来的。

一个文件，就是整个数据库

上一门课里，待办是存在一个 JSON 文件里的。这个项目换了个更正经的东西：SQLite。

它的特别之处是：整个数据库就是项目根目录下的一个文件，叫 signal-log.db。不用装服务，不用配账号。你把那个文件拷走，数据就跟着走了。

它像一本装订好的台站日志本：每一行一条记录，格式固定，翻起来快，因为它自带目录。

db.js:6-14

db.exec(`
  CREATE TABLE IF NOT EXISTS messages (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    created_at TEXT NOT NULL,
    callsign TEXT,
    origin TEXT,
    message TEXT NOT NULL,
    strength INTEGER NOT NULL
  );

执行下面这段建表语句。

IF NOT EXISTS 的意思是“已经有了就别再建”。所以这段每次启动都跑，但只有第一次真正生效。

id 是主键，自动递增。第一条是 1，第二条是 2，你不用管。

创建时间，NOT NULL 表示必填，留空数据库直接拒绝。

呼号，没写 NOT NULL，所以可以留空。

来源，同样可以留空。

留言正文，必填。“哪些能空、哪些不能空”这件事，在建表时就定死了，比写在代码里的检查更靠得住。

信号强度，必填，是个整数。

这张表定义完了。下面还有一张 reports 表专门放举报。

信号强度是编出来的

页面上那个 0 到 100 的信号强度看着很酷，其实它不是测出来的，是按留言长度算出来的。

db.js:95-100

function computeStrength(message, id) {
  const len = message.length;
  const base = Math.min(85, 20 + Math.floor((len / 300) * 65));
  const noise = hashInt(id) % 16;
  return Math.max(0, Math.min(100, base + noise));
}

算强度要两样东西：留言内容和它的编号。

先量一下留言多长。

基础分：从 20 起步，按长度往上加，最多加到 85。写得越长，信号越强。

再加一点噪声：把编号哈希一下取余数，得到 0 到 15 之间的一个数。

两个加起来，再夹进 0 到 100。注意这个噪声不是真随机——它由编号决定，所以同一条留言算多少次都是同一个值。

函数结束。

✦

确定性（deterministic）

同样的输入永远得到同样的输出，这样的函数叫确定性函数。它的好处是可以随时重算、可以放心缓存、出问题也能复现。真用 Math.random()，同一条留言刷新一次强度就变了，看起来像 bug。

先写一行，再回头补一个字段

这里有一个先有鸡还是先有蛋的问题：强度要用编号来算，可编号是插入之后数据库才给的。

    const id = insert.lastInsertRowid;
    const strength = computeStrength(message, id);
    updateMessageStrengthStmt.run(strength, id);
    return getMessageByIdStmt.get(id);
  });

刚插入的那一行拿到了什么编号，数据库会告诉你。

有了编号，现在才算得出强度。

把算出来的强度写回那一行。所以一条留言其实被写了两次：先插进去，再补一个字段。

最后把这一行完整读出来还回去，页面拿到的就是带强度的版本。

这一整块被包在 db.transaction 里。事务的意思是：这几步要么全成，要么全不算。

⚠

没有事务会怎样

插入成功了、回填强度时程序崩了，数据库里就留下一条 strength 为 0 的残缺记录。事务的作用就是让这种“做了一半”的状态根本不存在。
