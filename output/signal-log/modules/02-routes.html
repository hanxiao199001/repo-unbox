02

谁在管这些频道

接收站自己不存东西，它只负责把每一单指到对的地方。

一台收音机上的几个频道

server.js 一共对外开了五条 API 路由（另外还有一个 /admin 管理页面，第五模块讲）。它们就像一台收音机上的几个频道，每个频道播的东西完全不同：

GET /api/human-check

要一道算术题。服务器出题，同时给你一张一次性票据。

GET /api/messages

要一页留言。可以带搜索词和来源筛选，一页最多 50 条。

POST /api/messages

发一条新留言。这是唯一要过全部反垃圾检查的一条路。

POST /api/report/:id

举报某一条。谁都能用，不需要任何身份。

DELETE /api/messages/:id

删掉某一条。唯一一条要管理员钥匙的路，第五模块讲。

每一条这样的约定，工程界叫一条路由。前面那个大写的词是方法，表示你想干什么。

最简单的一条：出一道题

server.js:143-146

app.get('/api/human-check', (_req, res) => {
  const challenge = makeHumanCheck();
  return res.json(challenge);
});

这一行声明：走 GET、地址是 /api/human-check 的，交给下面这段处理。

参数名前面那个下划线是约定俗成的记号，意思是“这个参数我用不上”。这里确实用不上，因为出题不需要看你是谁。

出一道题。返回的东西里有题面和一张票据。

直接把它当 JSON 发回去，这条路到此结束。

ℹ

下划线开头的参数

写成 _req 而不是 req，是在告诉后来的人：我知道这个参数在，但我故意不用。很多代码检查工具也认这个约定，不会再提醒你“有个变量没用到”。

复杂一点的一条：要一页留言

server.js:148-156

app.get('/api/messages', (req, res) => {
  const limit = Math.max(1, Math.min(50, Number.parseInt(req.query.limit, 10) || 50));
  const offset = Math.max(0, Number.parseInt(req.query.offset, 10) || 0);
  const query = normalizeText(req.query.q, 100);
  const origin = normalizeText(req.query.origin, 64);

  const result = listMessages({ limit, offset, query, origin });
  return res.json(result);
});

走 GET、地址是 /api/messages 的，交给这段。

这一行做的事比看上去多：把地址里带的 limit 变成数字，然后夹在 1 和 50 之间。有人手动把地址改成 limit=99999，也只会拿到 50 条。

offset 是“从第几条开始”。它和 limit 配合就是翻页：第二页就是 offset=50。

搜索词，最多留 100 个字符。normalizeText 会把多余空格压掉再截断。

来源筛选，最多 64 个字符。

空行，作者用它把“整理参数”和“真正干活”分开。

把四个整理好的参数交给日志本，让它去查。接收站自己一条数据都不碰。

查到什么就发回什么。

这条路结束。

⚠

别相信地址栏里的任何东西

limit、offset、搜索词全是用户能随手改的。这段代码对每一个都做了限制：转成数字、夹进范围、截断长度。凡是从外面来的值，先当它是恶意的。

我按条件拼一句查询，顺便再数一次总共有多少条——你要翻页，得知道一共几页。

为什么 /api/messages 这一个地址下面挂了两条路由？

你朋友问“翻页到底是怎么翻的”。用不超过三句话讲给他听，不许用“分页器”这种词。

  • 说出了 limit 和 offset 这两个英文原词，并讲清楚各自是什么意思
  • 讲明白了 total 的作用是“知道还有没有下一页”
  • 用了一个你自己的说法，没有直接搬课程里的比喻
