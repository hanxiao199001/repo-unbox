你按下 TRANSMIT 之后

一条留言从输入框出发，到落进数据库为止。

先做一件你已经做过的事

SIGNAL LOG 是一个深空电台主题的留言板。你填一个callsign（呼号）、一个 origin（来源），写一句话，按下 TRANSMIT。

下一秒，你的留言出现在下面那条滚动的信号流最上面，旁边还有一个 0 到 100 的信号强度。

这门课要讲的，就是这一下按钮背后的事。不从“什么是数据库”开始讲，从你的手指开始讲。

A

public/app.js

浏览器里跑的那份。它收你敲的字、把信号流画出来、也负责把错误提示给你看。

S

server.js

接收站。所有请求先到它这儿，它负责分派，还负责把机器人挡在门外。

D

db.js

台站日志本。只有它碰数据库文件，留言最后落在它手里。

✦

关注点分离（separation of concerns）

画页面、接请求、存数据被拆给了三个文件。拆开不是为了好看，是为了出问题时你知道该先打开哪一个。

async function submitTransmission(event) {
  event.preventDefault();
  const form = event.currentTarget;
  const formError = document.getElementById('form-error');
  formError.textContent = '';

函数名 submitTransmission 直译是“提交一次发射”。这个项目从头到尾都在用电台的词。

preventDefault 挡掉浏览器的默认反应。不写这一行，整页会刷新一次。

拿到刚才被提交的那个表单。

找到显示错误的那个位置。

先把上一次的错误清空——不清的话，这次成功了旧的红字还挂在那儿。

public/app.js:192-199

  const payload = {
    callsign: form.callsign.value,
    origin: form.origin.value,
    message: form.message.value,
    humanAnswer: form.humanAnswer.value,
    humanToken: state.humanToken,
    website: form.website.value
  };

payload 就是这一单里真正要发出去的内容。

呼号，可以不填。

来源，也可以不填，不填就显示 Unknown。

留言正文，这个必须有。

那道算术题的答案。

题目对应的那张一次性票据，第三模块专门讲它。

这一行最有意思：website 是一个人类根本看不见的输入框。你永远是空的，填了内容的一定是机器人。
