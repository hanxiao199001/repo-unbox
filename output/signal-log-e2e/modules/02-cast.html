这个项目里都有谁

上一模块跟着一条留言走了一遍全程，路过了好几个文件名。这一模块停下来，把这几个文件当成几个角色，一个个认清楚：谁负责收发、谁只管硬盘、谁只管好看。

五个文件，五个分工

SIGNAL LOG 一共只有五个自己写的文件，就像一个开在网上的快递驿站：有人在窗口收件，有人在后头的仓库码货，还有人负责把门面装修得像回事。分工非常干净——每个文件只管一件事。

A

public/app.js

前台窗口。收你打的字，画你看到的页面，自己不留东西——关掉标签页，它记的一切都没了。

S

server.js

驿站的分拣员。谁发来的东西，先查一遍、分好类，再决定往哪儿送，自己从不留货。

D

db.js

后头的仓库。整个项目里只有它真正碰硬盘，货物进出都要经过它的账本。

H

public/index.html

门面的骨架。表单有几个输入框、按钮摆在哪，都是它说了算，但它不管好不好看。

C

public/styles.css

门面的装修。深蓝底色、荧光青边框，这一整套深空电台的味道全是它调出来的。

server.js：只负责派活，不留一件东西

server.js 用的是一个叫Express的框架。它的核心工作就是给每一条路由安排好该由哪段代码来接。下面这一段就是全项目里最短的一条路由——专门用来发一道人类验证题。

server.js:143-146

app.get('/api/human-check', (_req, res) => {
  const challenge = makeHumanCheck();
  return res.json(challenge);
});

这一行声明：只要有人拿 GET 方式访问 /api/human-check，就交给这个函数处理。

调用 makeHumanCheck，生成一道新的加法题和一次性凭证，自己不参与出题逻辑。

把结果转成一份大家能读的回复直接送出去——server.js 全程没有把这道题存进硬盘，转手就交出去了。

你会发现 server.js 里几乎每一条路由都是这个套路：接一下、查一下、转手交给别人，自己从不留东西。这也是为什么调试的时候，"数据丢了"这种问题从来不该先怪它。

db.js：不只是存东西，还会算账

整个项目只有 db.js 会碰那个叫 signal-log.db 的文件，用的是一个叫SQLite的轻量数据库。但它不只是"存进去、读出来"这么简单——每条新留言送到它手上时，它还会顺手给这条留言算一个信号强度。

db.js:95-100

function computeStrength(message, id) {
  const len = message.length;
  const base = Math.min(85, 20 + Math.floor((len / 300) * 65));
  const noise = hashInt(id) % 16;
  return Math.max(0, Math.min(100, base + noise));
}

先量出这条留言有多少个字符，字越多，等一下算出来的基础分越高。

base 是基础信号强度，最高封顶在 85，留言越长越接近这个上限。

noise 是拿这条记录的 id 算出来的一个 0 到 15 之间的余数，给每条留言添一点看起来随机的浮动。

最后把 base 和 noise 加起来，夹在 0 到 100 之间，这就是你在页面上看到的那个百分比。

ℹ

这个数字不是真的信号

signal-log.db 里存的这个 strength，本质上只是根据留言长度和 id 算出来的一个装饰性数字，跟真实的电台信号毫无关系——它的作用是让这个虚构的深空电台看起来更像那么回事。

前端三件套：骨架、装修、行为，一层层叠上去

public 目录下的三个文件，正好对应网页的三层：index.html 是DOM结构，styles.css 管外观，app.js 管交互。切一下下面这几个标签，看看同一个表单在不同阶段长什么样。

只有骨架：能看到表单和按钮，样式全无，点了也没有任何反应。
骨架加上装修：深空视觉出来了，但按钮和输入框仍然是摆设。
骨架、装修、行为三层叠满：点击 Transmit 真的会发出请求，页面才算完整地"活"了起来。

小结

五个文件、五种分工：app.js 收发，server.js 分拣，db.js 存货又算账，index.html 搭骨架，styles.css 管装修。记住这张分工表，往后不管是找 bug 还是加功能，第一件事都是先问一句"这该归谁管"。

现在要新增一条规则：留言里不能包含某个屏蔽词。这个判断最应该放在哪个文件里？

你想给每条留言加一个"点赞数"，点一下加一。把你会对 AI 说的那句指令原样写出来，想清楚它需要动哪几个文件。

  • 提到了 db.js 需要新增一个字段来存点赞数
  • 提到了 server.js 需要新增一条路由来接收点赞请求
  • 提到了 public/app.js 需要加一个按钮的点击处理
  • 没有要求把这个逻辑塞进 public/styles.css
